# GO-2026-6617 — Go stdlib go1.26.4 (embedded in TypeScript 7 native compiler)

**Status:** Proposed — pending human review
**Date drafted:** 2026-11-06
**Drafter:** Claude (cra-evidence) | **Decider:** [name — REQUIRED before status changes]

## Finding

- **Component:** Go stdlib go1.26.4, embedded in the `tsc` binary shipped by
  `@typescript/typescript-darwin-arm64` (transitive of `typescript@7.0.2` — dev dependency)
- **Source:** grype scan of compliance/sbom/v1.8.0.cdx.json, 2026-11-06
- **Severity:** High (per grype; Go advisory) — fixed in: 1.26.9
- **Summary:** HTTP/2 servers could end up crashing due to inadvertently modifying its HPACK
  encoder concurrently. This happens because the server modifies the HPACK
  encoder from two goroutines without synchronization: one uses the encoder to
  encode a HEADERS frame as part of a response sent to a client and the other
  modifies the encoder's table size when handling a SETTINGS frame containing
  SETTINGS_HEADER_TABLE_SIZE that a client sends. A malicious client can
  repeatedly send a request while changing the header table size to crash the
  server.

## Exploitability in context

- **Is the vulnerable code path reachable in this product?** No — the binary is the
  TypeScript 7 native type-checker (tsgo), run by developers and CI on the
  project's own sources. It is not part of the built site or the Docker image,
  never runs in production and processes no attacker-controlled input.
- **Exposure:** build-time only (developer machines and CI runners).
- **Existing mitigations:** the shipped product is static HTML/CSS/JS served by a
  CDN or by stock nginx; no Go code ships.
